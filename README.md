# TFCチーム記録ツール

THE FULL CREW のメンバーが、各自のランニング記録（距離・時間・ペース・心拍など）を
自分で入力し、先生（指導者）は全員の状況を横断的に見られる、チーム共有の記録ツール。

自分専用のマラソン記録サイト（`ランニング記録/` フォルダ）とは別物。あちらは1人用、
こちらはチーム全員が使う共有ツール。

## どこに何があるか

| | |
|---|---|

### Tetsuの記録を同期する

`ランニング記録/2_記録データ/ラン記録_マスター.csv` に新しい行を足したあと、
ターミナルで以下を実行すると、まだ登録されていない記録だけが追加される。

```
cd "/Users/mt/Documents/Claude Code/ランニング記録/TFCチーム記録ツール"
python3 sync_tetsu.py            # 追加する
python3 sync_tetsu.py --dry-run  # 追加せず内容だけ確認する
```

何度実行しても二重登録にはならない（日付＋距離が一致する記録はスキップする）。
心拍が空の行はツール側で心拍が必須のためスキップされる（2026-07-18の1件が該当）。

メモ欄について：CSVの「備考」は自分用の書き方（自己ベスト表記など）なので**同期しない**。
代わりに「Zone2 91%」のような客観的な数値だけを自動で入れる。
練習の中身（坂道・ロング走など）の振り返りを足したいときは、アプリの編集から手で書き足す
（2026-09-14に既存13件のメモを客観的な振り返りに書き直し済み）。

### Tetsuの記録を更新するときのルール（別の会話から更新する場合も同じ）

2026-09-15から、普段のラン記録を投げている別の会話でもこのツールへ反映している。
どこから更新する場合も以下を守る。

1. **追加は `python3 sync_tetsu.py` を使うのが基本**。直接Supabaseに書き込む場合も、
   同じ日付＋距離の記録がすでにないか先に確認する（二重登録防止）
2. **削除はできない設定になっている**（Supabase側で本当の削除を禁止）。
   間違えた記録は PATCH（更新）で直すか、`deleted_at` に日時を入れて隠す。
   「消して入れ直す」をすると、削除が黙って失敗して記録が2件になるので注意
3. **メモは客観的な内容だけ**（例：「平坦なコース。Zone2 91%、ピッチ174」）。
   マスターCSVの「備考」にある「過去最高」「自己ベスト」などの表現はチームに見えるので書かない
4. 心拍が空の記録は入れない（ツール側で心拍が必須）

### 週ごとの宿題タブ（2026-09-21）

資料タブの「宿題」に、先生が配布した資料の画像をそのまま表示する。
公開済み（2026-09-21に本人が齋藤さんへ確認。宿題はLINEグループで全員に配られているものなのでOK）。

宿題タブの中は、週ごとの配布資料に加えて「宿題ガイド」（最初に配られた説明資料・全3ページ）を
タブで切り替えられる。ガイドの画像は `images/homework/guide1〜3.jpg`
（原本 `3_先生からの資料/宿題/TFC週ごとの宿題ガイド.pdf` をページごとに画像化したもの）。

毎週の更新は2つ。
1. 配布画像を `images/homework/weekN.jpg` に置く（`sips -s format jpeg --resampleWidth 1200` 程度に縮めてから）
2. `index.html` の `HOMEWORK.weeks` の末尾に1つ足す（`label` / `range` / `theme` / `img`）
週が2つ以上になると、宿題タブの中に週の切り替えボタンが出る。
同じ内容は個人レポートサイト（`1_先生に見せるもの/公開サイト/index.html` の `WEEKLY_MENU`）にもあるので、
毎週どちらも更新する。宿題の原本は `3_先生からの資料/宿題/日付_第○週宿題_テーマ/`。

### コラムタブ（2026-09-21）

資料タブの「コラム」に、先生がLINEで毎週配信しているコラムを新しい順に並べている。
タップすると、LINEの本文を**文字**で、一緒に配られた図を**画像**で表示する
（LINEのスクショをそのまま載せるのはやめた。名前やアイコンが写り、見た目もいまいちなため）。

データは `columns.js`（`COLUMNS` の配列）。新しいコラムを足すときは2つ。
1. 図がある場合は `images/columns/YYYYMMDD/2.jpg`, `3.jpg`… に置く（横1200px程度）
2. `columns.js` の末尾に `{ date, title, figs, text }` を1つ足す。`text` はLINE本文の文字起こし

原本は `3_先生からの資料/コラム/日付_タイトル/`（スクショ・図・文字起こし `日付_配信本文.txt`・要点 `日付_本文.md`）。

### 宿題の記録（2026-09-22・有効）

「記録する」で、今日やったのが宿題のどれか（ロング走／ゆっくりラン／補強だけ／それ以外）を選べる。
- レベル（ライト／スタンダード／チャレンジ）は**任意**。「記録する」右上の「宿題のレベル」を押した人だけ選ぶ。選ばない人には宿題の達成状況も出ない
- 「補強だけ」は走らないので、日付だけで記録（`strength_logs` 表）。取り消しもできる
- ロング走・ゆっくりランを選ぶと、同じ種類の前回の記録をコピーできる
- 達成状況は**自分にだけ**見せる（ホームの宿題タイル・自分のページ）。「みんな」には出さない。
  「もっと走れ」と感じさせないための配慮（本人の希望）。表現も「目標」ではなく「目安」
- 平均心拍は任意にする（本人と合意）
- 判定：ロング走は目安の時間以上の1本があれば達成、ゆっくりラン・補強は回数
- 毎週の宿題を足すときは、`HOMEWORK.weeks` に `start` / `end` / `targets`（レベル別の longMin・easy・easyMin・strength）も入れる

`20260922_宿題の記録.sql` は2026-09-22にSupabaseで実行済み（心拍も任意になった）。
アプリは起動時に列・表があるかを確認し、なければ今までどおりの画面で動く作りのまま。

## このツールの立ち位置（トーン）

作者は先生ではなくメンバーの一人。「自分の記録はどうせつけるので、情報量も増えてきたしここにまとめた。
みんなもよかったら使ってみてね」くらいのテンション。宿題も強制ではない。
画面の文言・案内文は、走れ・速く走れ・宿題をやれ と感じさせないように書く。

## 仕組みのポイント（あとで思い出すためのメモ）

- **識別方法**：名前を選ぶだけ（PINなし）。当初PINもあったが、Supabase側がそもそも
  誰でも読み書きできる設定なので実質的なセキュリティ効果がないと判断し撤廃した。
  ブラウザに記憶されるので毎回選び直す必要はない
- **公開範囲**：当初は「本人＋先生のみ」の想定だったが、もともとLINEグループで
  日々の記録を共有する文化があり見られる抵抗感が薄いとわかったため、
  「みんなの状況」タブで全メンバーの走行状況（直近7日/30日の距離・最終記録日・
  直近RPE・メモ）を全員に公開する方針に変更した（2026-09-06）。
  なお技術的にはSupabase側は誰でも読み書きできる設定なので、そもそも厳密な
  非公開の保証はない。少人数の信頼できるチーム前提の割り切り
- **先生の見分け方**：DB上は「先生」ロールを持つ人が1人いる（バッジ表示用）。
  ただし機能的な区別はもう無く、先生専用のログインや画面はない
- **画面構成（2026-09-22に再編）**：下のタブは「ホーム／資料／記録する／みんな」の4つ（スマホではアイコン付き）。
  情報が主役・記録はおまけ、という立ち位置に合わせた並び。開くと最初に**ホーム**が出る。
  ホームは、上の帯に「勝田まで○日」と「次の練習会」（名前を選んだ人には小さく「あなたの今週」）、
  その下に 宿題・コラム・ガイド・記録する の4つの四角いタイル。
  配信から7日以内の宿題・コラムには「NEW」を付ける。週は月曜はじまりで数える
- **みんな**：メンバー全員を並べる（自分が一番上、そのあと記録が新しい順）。ホームには出さず、みんなタブを開いた人にだけ見える
- **宿題・コラム**：「LINEで配信されたものを、あとからまとめています」と書き添えている（正式な配布はLINE）
- **名前の選び方**：ヘッダーの選択欄はやめた。名前を選んでいない人が「記録する」を
  開くと、メンバー名の大きなボタンが並ぶ画面が出る。選ぶと端末に記憶される。
  「記録する」の上に「○○ さん／別の人に切り替える」を出している
- **自分の記録（2026-09-22に「みんな」へ統合）**：以前は「自分の記録」タブがあったが、
  「みんな」から見る自分のページと中身が同じだったため統合した。「みんな」の一覧では自分が
  一番上に「あなた」付きで出て、自分のページだけ記録の編集・削除ボタンが付く
- **資料タブ**：上のボタンで 宿題／コラム／日程／リンク を切り替え。
  「日程」は練習会・大会・申込の締切を日付順に並べたもの（終わった予定は薄く、次の予定に「次」の印）。
  「リンク」は TFC ナレッジベース／参加者ガイド／勝田マラソン公式の一覧で、選ぶとページ内に埋め込み表示。
  埋め込みの高さは画面の残りぴったりに合わせ、ページ全体はスクロールさせない（二重スクロール防止）。
  上に「← リンク一覧」と「別のタブで開く」を置いている
- **日程データ**：`index.html` の `SCHEDULE`。kind は practice（練習会）／race（大会）／entry（申込）。
  `until` を書くと受付期間、`dateLabel` を書くと「1月上旬」のような表記にできる。
  ホームの「次の練習会」はここから拾っていて、タップすると日程タブが開く
- **大会設定**：以前あった「⚙ 大会設定」フォームは、誰でも触れてカウントダウンがずれる恐れがあるため
  2026-09-15に削除し、Supabase側でも大会設定を読むだけにした。
  変更が必要なときはSupabaseのSQL Editor（管理者）で race_config を直接更新する
- **記録を保存したとき**：「記録を保存しました。今週 ○km（○本）です。」と今週の合計も出す
- **モバイル最適化（2026-09-09）**：スマホ利用がメインのため、620px以下では
  レイアウトを切り替えている。①タブバーを画面下に固定（親指で届く位置）
  ②記録一覧の表を1件=1カードに積み直して横スクロールを解消
  ③入力欄を16pxにしてiOSの自動ズームを防止 ④ボタンのタップ領域を拡大
  ⑤ヘッダーを圧縮（THE FULL CREWを1行に、eyebrowを非表示）。
  PC幅では従来どおり上部タブ＋表形式で表示される
- **記録項目**：距離・時間・ペース・心拍は必須（すべて時計の表示をそのまま手入力）。
  ピッチ・接地時間・体感(RPE)・メモは任意
- **入力の手間を減らす工夫**：ペースは距離と時間から自動計算（空欄のときだけ）。
  ピッチ・接地時間は前回値を初期値に引き継ぐ。「前回の記録をコピー」ボタンで
  同じような練習の日はワンクリックで全項目コピーできる
- **削除は「隠すだけ」（2026-09-14）**：削除ボタンは記録に `deleted_at`（削除日時）を入れて
  画面から隠すだけ。誤って消しても、Supabaseでその列を空に戻せば復活する。
  あわせてアプリのキーでは本当の削除（記録・メンバー・大会設定）をできない設定にした。
  他人の記録を編集・削除できてしまう点は、ログインなしの設計上の割り切り
- **入力ミスの確認（2026-09-14）**：距離50km超、心拍60未満/210超、未来の日付、
  距離×時間から計算したペースと入力ペースが15%以上違う、などのときは保存前に確認を出す
  （保存は止めない）
- **検索よけ**：`<meta name="robots" content="noindex">` で検索エンジンに載らないようにしている
- **バックアップ**：Supabase無料プランは自分でバックアップを取り出せないため、
  `python3 backup_records.py` で月1回程度、手元に保存する
